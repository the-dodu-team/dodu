# 1. Product Concept

## 1.1 서비스 한 줄 정의

> **스스로 정한 개인작업의 시작 약속을 실제 행동으로 연결하도록 돕는 시작 행동 지원 서비스**

## 1.2 현재 제품이 다루는 문제 범위

이번 MVP는 생산성 관리 전체를 해결하지 않는다.

다루는 범위는:

> **해야 할 일과 시작 방법이 대체로 명확함에도 혼자 수행하는 개인작업의 계획한 시작 시점을 반복적으로 넘기는 상황**

이다.

### 이번 MVP에서 직접 다루지 않는 문제

- 무엇을 해야 할지 결정하지 못하는 문제
- 작업 우선순위를 정하지 못하는 문제
- 복잡한 작업을 세분화하는 문제
- 피로·건강 상태 자체의 해결
- 외부 일정 충돌 자체의 해결
- 작업 지속시간 관리
- 집중 유지
- 작업 완료 관리

# 2. Product Principles

제품·디자인·개발의 세부 판단이 충돌할 경우 아래 원칙을 우선 기준으로 사용한다.

## 2.1 사용자가 스스로 약속한다

서비스가 작업을 임의로 배정하지 않는다.

사용자가 직접:

- 어떤 작업을
- 언제 시작할 것인지

정한 이후 서비스 개입이 시작된다.

## 2.2 현재 제품의 목표는 ‘완료’가 아니라 ‘시작’이다

이번 MVP에서는:

- 작업 완료율
- 작업 지속시간
- 집중도

보다 **계획한 시점에서 실제 시작 행동으로 이동하는 과정**에 집중한다.

## 2.3 계획보다 행동에 개입한다

새로운 To-do나 일정관리 도구를 만드는 것보다, 이미 정한 계획이 **실제 행동으로 넘어가는 순간**에 개입한다.

## 2.4 실패가 다음 시도를 막지 않는다

한 번 또는 반복된 미인증이:

- 서비스 이용 정지
- 재도전 불가
- 회복 불가능한 상태

로 이어지지 않도록 한다.

## 2.5 관찰하지 못한 행동을 성공으로 간주하지 않는다

사진 인증 성공은:

> **작업환경 행동 요구에 응답했다**

는 의미이며,

> **실제 작업을 시작했다**

는 의미로 간주하지 않는다.

시스템 로그와 자기보고 결과를 구분해 해석한다.

## 2.6 개입 강도는 검증 결과에 따라 높인다

이번 MVP에서는:

- 포인트 손실
- 등급
- 보상
- streak
- 사회적 압력

등을 기본 전제로 사용하지 않는다.

더 강한 개입의 필요성이 확인될 경우 이후 버전에서 별도로 검토한다.

# 3. 사용자 문제

## 3.1 확인된 문제

> **개인작업의 시작을 반복적으로 미루는 실제 경험이 존재하며, 이로 인해 일정 지연·중단·포기 등 실제 작업 진행에 부정적인 영향을 받을 수 있다.**

설문과 심층 인터뷰에서 개인작업의 시작 지연 경험이 확인됐다.

심층 인터뷰에서는 동일한 `시작을 미룬다`는 행동이 서로 다른 상황에서 나타났다.

### 인터뷰에서 확인된 주요 상황

- 여러 작업 중 무엇을 먼저 해야 할지 판단하기 어려움
- 해야 할 일과 방법을 알고도 실행하지 않음
- 다른 외부 일정에 밀림
- 피로·컨디션 저하
- 작업 자체에 대한 흥미 부족

따라서 시작 지연을 하나의 원인으로 설명하지 않는다.

## 3.2 기존 해결 방법의 반복 한계

인터뷰 참가자들은 이미:

- To-do
- 캘린더
- 일정 관리
- 타이머
- 스터디
- 장소 변경
- 챌린지
- AI 보조도구

등을 사용한 경험이 있었다.

하지만 반복적으로:

> **계획·정리는 했지만 실제 시작으로 이어지지 않는 간극**

이 확인됐다.

이번 제품은 새로운 계획 관리 도구를 추가하기보다 이 간극을 우선적으로 다룬다.

# 4. 목표 사용자

## 4.1 핵심 사용자

> **해야 할 개인작업과 시작 방법을 대체로 알고 있지만, 혼자 수행하는 개인작업에서 계획한 시작 시점을 반복적으로 넘기는 성인**

### 대표 작업

- 포트폴리오
- 개인 공부
- 개인 프로젝트
- 컴퓨터 또는 책을 주요 도구로 사용하는 개인작업

### 이번 가설 검증과 상대적으로 관련성이 높은 경험

- 혼자 할 때는 미루지만 타인과의 약속이나 일정이 있으면 상대적으로 행동하기 쉬웠던 경험
- 일정이나 할 일을 정리하고도 실제 시작하지 못했던 경험

### 이번 핵심 범위에서 제외

- 무엇을 해야 할지 전혀 결정하지 못한 작업
- 팀 단위 수행이 필수인 작업
- 외부 마감·타인 요구가 이미 강하게 작동하는 업무
- 현재 인증 카테고리로 다루기 어려운 작업

---

# 5. 우선 원인 가설

> **해야 할 작업과 방법을 알고 있는 사용자도, 혼자 수행하는 개인작업에서는 타인과의 약속이나 일정처럼 행동을 요구하는 외부 책임이 상대적으로 약해 계획한 시작을 뒤로 미루기 쉬울 것이다.**

## 5.1 근거

심층 인터뷰에서:

- 해야 할 일을 알고도 시작하지 않는 사례가 확인됐다.
- 타인과의 약속이나 일정이 있는 환경에서 상대적으로 행동하기 쉬웠던 경험이 확인됐다.
- 일정·페널티 등 외부 책임이 있을 때 행동하게 된 일부 사례가 있었다.
- 기존 일정관리·체크리스트를 사용하고도 실제 시작하지 못하는 경험이 반복됐다.

## 5.2 해석 범위

외부 책임 부족이:

- 모든 사용자의 시작 지연 원인이라고 보지 않는다.
- 시작 지연의 가장 중요한 단일 원인이라고 확정하지 않는다.

이는 인터뷰에서 확인된 여러 요인 중 **이번 MVP에서 제품으로 개입할 가능성을 우선 검증하기 위해 선택한 원인 가설**이다.

## 5.3 이번 원인을 우선 선택한 이유

- 해야 할 일을 이미 알고 있어도 문제가 발생함
- 기존 계획·관리 도구가 해결하지 못한 `계획 → 실행` 간극과 직접 연결됨
- 제품이 실제 시작 시점에 개입할 수 있는 영역임
- 피로·외부 일정 등 다른 요인보다 현재 제품을 통한 개입 가능성이 상대적으로 높음

# 6. Value Hypothesis

> **계획 자체보다 실제 시작으로 이동하는 순간에 도움을 필요로 하는 사용자는, 자신이 정한 시작 시점에 다시 행동을 요구하는 외부 개입을 사용할 가치가 있다고 느낄 것이다.**

### 아직 확인되지 않은 것

- 사용자가 이런 개입을 자발적으로 사용할 것인가
- 행동 요구가 지나친 통제로 느껴지지 않는가
- 사진 인증 방식을 수용할 수 있는가
- 미인증 경험 이후 다시 약속을 생성하는가
- 반복해서 사용할 가치가 있는가

---

# 7. Solution Hypothesis

## 7.1 상위 솔루션 가설

> **사용자가 스스로 정한 시작 시점에 서비스가 실제 행동을 요구하면 실제 작업 시작으로 이동하는 데 도움이 될 것이다.**

## 7.2 작업환경 행동 요구 가설

> **사용자가 작업도구가 있는 환경으로 이동해 인증 행동을 수행하도록 요구하면 실제 작업 시작에 가까운 준비 행동을 유도할 수 있을 것이다.**

사진 인증은 이 가설을 검증하기 위해 선택한 이번 MVP의 구현 방식이다.

사진 인증 자체가 최선의 방식이라고 확정하지 않는다.

## 7.3 인증 결과 피드백 가설

> **사용자가 자신이 설정한 시작 약속에 대해 실제로 인증까지 행동한 기록을 확인할 수 있으면 이후 자신의 시작 행동을 인식하는 데 도움이 될 것이다.**

본 가설의 효과는 아직 확인되지 않았다.

이번 MVP에서는 아래 메커니즘을 핵심 행동 개입으로 사용하지 않는다.

- 포인트 손실

- 등급
- streak
- 배지

- 사회적 공개·비교

이들은 이번 검증 결과에서 더 강한 개입이 필요하다고 판단될 경우 후속 후보로 검토한다.

# 10. 핵심 사용자 흐름

## 10.1 정상 흐름

작업 약속 설정  
→ 시작시간 도달  
→ 시작 알림  
→ 인증 화면 진입  
→ 작업도구가 있는 환경으로 이동  
→ 사진 촬영·제출  
→ 인증 성공  
→ 인증 완료 기록  
→ 시작 개입 종료

## 10.2 미인증 흐름

시작시간 도달  
→ 시작 알림  
→ 인증하지 않음  
→ 인증 가능 상태 유지  
→ 필요 시 사용자가 자발적으로 인증 화면 재진입  
→ 미인증 상태이면 정책에 따른 재알림  
→ 인증 가능 시간 종료까지 인증하지 않음  
→ 인증 미완료 기록  
→ 시작 개입 종료

### 재알림의 역할

재알림은 새로운 인증 권한이나 새 인증 세션을 부여하는 기능이 아니다.

> **아직 인증하지 않은 사용자에게 인증 가능 상태와 시작 행동을 다시 상기시키는 리마인드**

로 작동한다.

인증 가능 시간과 재알림 시점은 서로 분리하여 관리한다.

## 10.3 기술오류

기술오류는 사용자 미인증과 분리한다.

서비스 또는 판정 시스템 문제 때문에 정상 인증할 수 없는 경우 이를 사용자의 실패로 기록하지 않는다.

정확한 오류·복구 정책은 서비스 운영 정책에서 관리한다.

## 10.4 실제 작업 시작

인증 완료 여부와 실제 작업 시작 여부는 별개다.

실제 시작은:

- 시스템 로그
- 행동검증용 일일 자기보고
- 사후 인터뷰

를 함께 사용해 보조적으로 확인한다.

# 11. 기능 요구사항

## F-01. 작업 약속 설정

### 목적

사용자가 어떤 개인작업을 언제 시작할 것인지 명시적인 시작 약속으로 만든다.

### 사용자가 할 수 있어야 하는 것

- 작업명 입력
- 시작시간 설정
- 인증할 작업도구 카테고리 선택
- 약속 내용 확인
- 약속 저장

### 서비스 동작

- 작업 약속 저장
- 활성 약속 상태 관리
- 시작시간 기준 알림 준비
- 인증 카테고리 저장

예약 가능 시간 범위와 행동검증 종료일을 넘는 예약 제한 등 정확한 운영값은 서비스 운영 정책에서 정의한다.

---

## F-02. 시작시간 알림

### 목적

계획으로 끝난 약속을 실제 행동으로 연결하기 위해 약속한 시작 시점에 다시 개입한다.

### 사용자가 할 수 있어야 하는 것

- 알림 확인
- 인증 화면으로 이동

### 서비스 동작

- 시작시간에 알림 발송
- 시스템 발송 단계와 실제 사용자 행동을 구분하여 기록

---

## F-03. 작업환경 행동 요구 — 사진 인증

### 목적

사용자가 작업도구가 있는 환경으로 이동하도록 실제 행동을 요구한다.

### 중요한 정의

사진 인증은:

> **실제 작업 시작을 증명하는 기능이 아니다.**

이번 MVP에서 작업 시작에 더 가까운 준비 행동을 요구하기 위해 선택한 개입 방식이다.

### 사용자가 할 수 있어야 하는 것

- 카메라 권한 허용
- 등록 카테고리에 맞는 작업도구 촬영
- 제출 전 재촬영
- 사진 제출
- 판정 결과 확인
- 판정거절 시 인증 가능 시간이 남아 있다면 재촬영·재제출
- 인증 가능 시간이 남아 있다면 다시 인증 화면에 진입해 재시도

### 서비스 동작

- 사진 제출 처리
- 등록 카테고리와 이미지 판정
- 성공 / 판정거절 / 기술오류 구분
- 판정거절 시 인증 가능 시간이 남아 있으면 재촬영·재제출 허용
- 인증 가능 시간이 남아 있으면 이후 재진입 허용
- 기술오류는 판정거절 및 사용자 미인증과 분리
- 성공 시 인증 완료 상태 기록

구체적인 인증 가능 종료 시점은 서비스 운영 정책에서 정의한다.

### MVP에서 확인할 위험

- 사용자가 사진 인증 목적을 이해하는가
- 실제 작업도구가 있는 환경으로 이동하는가
- 인증이 지나친 추가 부담이 되는가
- 인증 이후 실제 작업을 시작하는가
- 인증만 하고 다시 이탈하는가
- 판정 오류가 시작 행동을 방해하는가

---

## F-04. 미인증 시 유예·재알림

### 목적

첫 개입 이후에도 인증하지 않은 사용자에게 시작 행동을 다시 상기시킨다.

### 핵심 원칙

> **재알림과 인증 가능 상태는 별개의 정책이다.**

재알림은 인증 권한을 새로 열거나 새 인증 세션을 시작시키지 않는다.

### 서비스 동작

- 시작시간 이후 정책상 정해진 인증 가능 시간 동안 인증 가능 상태 유지
- 사용자는 인증 가능 시간 안에서 서비스에 자발적으로 재진입해 인증 가능
- 미인증 상태가 유지될 경우 정책상 정해진 시점에 재알림 발송
- 재알림을 통해 인증 화면으로 이동 가능
- 인증 가능 시간이 종료될 때까지 인증하지 않으면 인증 미완료 상태로 개입 종료

### 주의

재알림은 포인트 손실이나 기타 페널티와 연결하지 않는다.

정확한 인증 가능 시간, 재알림 횟수 및 간격은 서비스 운영 정책에서 정의한다.

---

## F-05. 시작 인증 기록 피드백

### 목적

사용자가 자신이 만든 시작 약속에 대해 실제로 인증 행동까지 이어졌는지 확인할 수 있게 한다.

### MVP 제공 범위

- 최근 시작 약속의 인증 결과
- `인증 완료 / 인증 미완료`
- 필요 시 일정 기간의 단순 인증 횟수 요약

예:

- 월 · 인증 완료
- 화 · 인증 완료
- 수 · 인증 미완료

또는:

> 이번 주 시작 인증 3 / 5

### 표현 원칙

다음 표현은 실제 작업 시작을 직접 확인하지 못하므로 사용하지 않는다.

- 약속 성공 / 실패
- 약속을 지킴 / 어김
- 시작 성공률
- 작업 수행률

### 제외

- 포인트
- 등급
- streak
- 배지
- 랭킹

### 역할

본 기능은 사용자를 평가하거나 처벌하기 위한 점수가 아니라, **시스템이 실제로 확인한 시작 인증 행동을 사용자에게 되돌려주는 피드백**이다.

구체적인 노출 방식과 정보량은 디자인 UT에서 사용성과 수용성을 확인해 조정할 수 있다.

---

## F-06. 시작시간 수정·취소

### 목적

실제 일정 변경을 허용하되 사용자가 만든 시작 약속 자체가 지나치게 가볍게 변경되지 않도록 한다.

### 사용자가 할 수 있어야 하는 것

- 정책상 허용된 범위에서 시작시간 변경
- 정책상 허용된 범위에서 약속 취소

정확한 시간·횟수·예외 규칙은 서비스 운영 정책에서 정의한다.

---

## F-07. 검증용 행동 데이터 기록

### 목적

시작 시점의 개입 이후 실제로 어떤 행동이 발생했는지 확인하기 위한 원본 데이터를 확보한다.

### 주요 기록 범주

- 약속 생성
- 시작시간
- 약속 수정
- 약속 취소
- 알림 발송
- 인증 화면 진입
- 사진 촬영·제출
- 판정 결과
- 재시도
- 인증 완료 시각
- 유예
- 재알림
- 최종 인증 상태
- 인증 이력 확인
- 권한 상태
- 기술오류

### 원칙

집계된 결과만 저장하지 않고 **약속별 원본 행동 이력**을 보존한다.

후속 버전에서:

- streak
- 포인트
- 등급
- 개인화

등을 검토하더라도 기존 행동 데이터를 활용할 수 있도록 한다.

구체적인 이벤트·필드·연결키·계산식은 로그-검증 매핑표를 따른다.

---

## F-08. 참가자 식별 및 온보딩

### 목적

행동검증 참가자가 서비스 구조와 필요한 환경을 이해하고 개별 행동 데이터를 연결할 수 있도록 한다.

### 주요 요구

- 참가자별 식별
- 서비스 목적 및 사용법 안내
- 플랫폼 환경 안내
- 알림 권한 준비
- 최초 인증 시 카메라 권한 준비
- 행동검증 참여 조건 확인

정식 회원가입·소셜 로그인은 이번 MVP에서 제외한다.

---

## V-01. 행동검증용 일일 자기보고 설문

> **정식 제품 핵심 기능이 아니라 행동검증을 위한 별도 측정 요소**

### 목적

시스템 로그만으로 직접 확인할 수 없는:

- 실제 작업 시작 여부
- 인증 이후 실제 시작까지의 대략적인 시간
- 미시작 당시 맥락

을 보조적으로 확인한다.

진행자의 직접 연락이 외부 책임 요소로 작용하는 것을 줄이고, 당일 작업 흐름에 검증용 접촉이 끼어드는 것을 최소화하기 위해 **해당 약속 경험을 다음날 회고하는 방식**으로 제공한다.

### 운영 원칙

- 약속이 발생한 다음날을 기본 자기보고 시점으로 사용
- 행동검증 기간에만 사용
- 검증 목적임을 참가자에게 사전에 고지
- 다음날 첫 서비스 진입 시 미작성 설문이 있다면 비강제 안내 가능
- 미작성 상태가 지속될 경우 정책상 정해진 시각에 1회 리마인드 가능
- 응답 여부가 인증 결과에 영향을 주지 않음
- 응답 여부가 서비스 이용 가능 여부에 영향을 주지 않음
- 새 약속 생성을 설문 작성과 연결하지 않음
- 응답에 보상·포인트·손실을 연결하지 않음
- 미응답을 실제 작업 미시작으로 간주하지 않음
- 일정 시간이 지나면 미응답으로 종료
- 행동에 미치는 영향을 최소화하도록 짧고 중립적으로 구성

구체적인 최초 노출 조건, 리마인드 시각, 만료시간은 서비스 운영 정책에서 정의한다.

### 분석 한계

반복적인 자기보고 자체가 자신의 행동을 인식하게 해 이후 행동에 일부 영향을 줄 가능성을 배제하지 않는다.

### 기본 문항

#### 1. [예정 시작일시]의 시작 약속 이후 실제 작업을 시작했나요?

- 예
- 아니오

#### 2. 시작했다면 인증 후 언제쯤 실제 작업을 시작했나요?

- 바로 시작함
- 5분 이내
- 15분 이내
- 15분 이후

#### 3. 시작하지 못했다면 가장 가까운 이유는 무엇인가요?

- 피로·컨디션
- 다른 일정 발생
- 하기 싫음·흥미 부족
- 인증 후 다른 행동으로 이탈
- 기타

# 12. 검증 계획

## 12.1 1차 — 디자인 프로토타입 UT

### 목적

제품 효과가 아니라:

- 이해 가능성
- 사용성
- 수용성

을 확인한다.

### 주요 확인

- 사용자가 시작 약속의 의미를 이해하는가
- 약속 생성 흐름을 완료할 수 있는가
- 시작 알림 이후 해야 할 행동을 이해하는가
- 사진 인증의 목적을 이해하는가
- 실제 작업도구 촬영 요구를 수용할 수 있는가
- 인증 과정이 지나친 부담이 되는가
- 판정거절·재시도 흐름을 이해하는가
- 재알림을 이해하는가
- 인증 기록 피드백을 정확히 이해하는가
- 미인증 상태가 과도한 실패감으로 이어지지 않는가

### UT에서 주장하지 않는 것

- 실제 작업 시작 증가
- 미루기 감소
- 장기 행동 변화

---

## 12.2 2차 — 개발 MVP 행동검증

### 목적

실제 개인작업 상황에서 시작 시점 개입 이후 어떤 행동이 관찰되는지 확인한다.

### 시스템 로그로 확인

- 약속 생성
- 반복 약속 생성
- 시작시점 개입 도달
- 알림 이후 서비스 진입
- 인증 시도
- 인증 완료
- 인증까지의 지연
- 재알림 이후 행동
- 최종 인증 상태
- 인증 기록 피드백 확인

### 자기보고로 보조 확인

- 실제 작업 시작 여부
- 인증 이후 실제 시작까지의 시간
- 미시작 이유

### 사후 인터뷰로 확인

- 사진 인증이 작업환경 이동에 실제로 도움이 되었는가
- 인증만 하고 작업을 시작하지 않은 적이 있었는가
- 시작한 날과 시작하지 못한 날의 차이는 무엇이었는가
- 어떤 개입 요소를 가장 의식했는가
- 개입이 부담스럽거나 통제처럼 느껴졌는가
- 개입 때문에 약속 생성을 피한 적이 있는가
- 반복해서 사용할 의향이 있는가
- 더 강하거나 다른 개입이 필요하다고 느꼈는가

# 14. Go / 부분 Go / No-go 판단 원칙

이번 검증은 소규모 초기 검증이므로 통계적 인과관계를 증명하지 않는다.

행동 신호·자기보고·사후 인터뷰를 종합해 다음 제품 결정을 내린다.

## Go

다음 방향의 신호가 반복적으로 확인되는 경우:

- 사용자가 자발적으로 시작 약속을 생성함
- 시작시점 개입에 실제로 반응함
- 작업환경 인증 행동으로 이동함
- 인증 이후 실제 작업 시작으로 이어지는 사례가 반복적으로 관찰됨
- 인증 과정이 수용 가능한 수준임
- 사용자가 다시 약속을 생성함

→ 현재 해결 방향을 유지하고 반복 사용 경험 또는 다음 개입 강도를 검토한다.

## 부분 Go

예:

- 시작 행동 신호는 있으나 사진 인증 부담이 큼
- 시작 시점 개입은 유효하나 인증 방식에 문제가 있음
- 사용성 문제 때문에 행동 흐름이 방해됨
- 인증은 이루어지지만 실제 시작과의 연결이 일부에 그침

→ 우선 원인 가설 또는 해결 방향 전체를 폐기하지 않고 구체적인 구현 방식을 수정한 뒤 재검증한다.

## No-go

예:

- 사용자가 시작 약속 자체를 거의 만들지 않음
- 시작시점 개입에 의미 있는 반응이 거의 없음
- 인증 행동은 발생하지만 실제 작업 시작과 거의 연결되지 않음
- 인증 요구가 제품 사용 자체를 회피하게 만듦
- 반복 사용 의향이 매우 낮음

→ 현재 솔루션 가설 또는 필요 시 우선 원인 가설을 재검토한다.

---

# 15. 검증 해석 원칙

- 사진 인증 완료를 실제 작업 시작으로 계산하지 않는다.
- 일일 자기보고는 시스템 로그와 별도의 보조 자료로 사용한다.
- 미응답은 작업 미시작으로 계산하지 않는다.
- 피로·외부 일정 등 제품 개입과 직접 관계없는 미시작 맥락을 별도로 구분한다.
- 기술오류로 정상 인증이 불가능한 경우 사용자 행동 실패로 해석하지 않는다.
- 소규모 검증 결과로 통계적 유의성이나 제품 효과의 인과관계를 주장하지 않는다.
- 인증 이후 실제 시작 사례가 관찰되더라도 사진 인증이 원인이라고 단정하지 않는다.

---

# 16. Post-MVP Decision Framework

다음 버전의 기능은 현재 시점에서 확정하지 않는다.

행동검증 결과에 따라 가장 큰 다음 불확실성을 선택한다.

| 관찰 결과 | 해석 후보 | 다음 검토 방향 |
|---|---|---|
| 현재 개입만으로 실제 시작 신호가 충분 | 기본 방향 가능성 | 반복 사용·진행 피드백 고도화 |
| 개입에는 반응하지만 행동 동기가 약함 | 개입 강도 부족 가능성 | 손실·보상·stake 등 추가 개입 검토 |
| 미인증 경험 이후 약속 자체를 회피 | 통제·실패 부담 가능성 | 긍정적 피드백·개입 강도 완화 |
| 사진 인증이 지나치게 번거로움 | 행동 요구 방식 문제 | 더 가벼운 인증 방식 탐색 |
| 인증은 하지만 실제 작업 시작 안 함 | 인증이 대리 행동에 그침 | 실제 시작에 더 가까운 행동 요구 탐색 |
| 약속 자체를 거의 만들지 않음 | 가치 가설 문제 가능성 | 사용자·문제·제품 가치 재검토 |
| 사용자별 반응 차이가 큼 | 동일한 개입의 한계 | 개인화 가능성 탐색 |

# 17. 개발 확장 원칙

## 17.1 미래 기능을 미리 개발하지 않는다

추후 가능성만을 이유로 다음 기능을 미리 구현하지 않는다.

- 포인트 지갑
- 등급
- streak
- 배지
- 캐릭터
- 보상 상점
- 사회적 비교 시스템

## 17.2 실제 행동 데이터는 남긴다

후속 의사결정에 활용할 수 있도록 다음 정보는 원본 단위로 보존한다.

- 사용자
- 작업 약속
- 시작시간
- 알림
- 인증 시도
- 판정 결과
- 인증 완료
- 유예·재알림
- 최종 인증 상태
- 반복 약속
- 기술오류

향후:

- 포인트
- streak
- 행동 패턴 분석
- 개인화

등은 이 행동 구조 위에 추가할 수 있도록 한다.

세부 데이터 모델은 개발팀이 결정한다.
