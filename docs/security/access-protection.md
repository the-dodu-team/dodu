# 참가자 접근 보호 — SCRUM-70

## 승인된 정책 (사용자, 2026-10-08)

- 참가자 코드 입력 실패만 IP별 최근 10분 동안 누적한다. 10번째 실패부터 15분 차단한다.
- 실패 창은 `(현재-10분, 현재]`, 차단 만료시각부터 재진입 가능하다.
- 차단 중 요청은 만료시각을 연장하지 않는다. 사진 재제출·네트워크 오류·봇 검증 오류는 코드 실패가 아니다.
- IP 공유 환경의 정상 참가자도 영향을 받을 수 있으며 IP 제한만으로 분산 공격을 막을 수는 없다.

## 구현 범위

`CodeFailureWindow`는 불변 상태 전이만 구현한다. HTTP 로그인·IP 추출·공유 저장·운영 차단은 아직 없다.
통합 시 서버 시간으로 IP 키별 원자적 검사/실패 기록을 수행하고, 차단 상태는 HTTP 429와 올림한 Retry-After 초로 반환한다.
성공한 코드 입력이 IP 실패 기록을 초기화하도록 하지 않는다(유효 코드 하나로 공격자가 제한을 초기화하는 것을 방지).
프로세스별 메모리 상태만으로 다중 서버/재시작에 안전하다고 주장하지 않는다. 저장소 TTL·키 수 상한·동시 요청 검증 필요.
X-Forwarded-For 등 클라이언트 임의 헤더를 신뢰하지 않는다. 실제 신뢰 프록시 경로·원본 서버 직접 접근 차단을 확정해야 한다.
원문 IP·코드·토큰을 디버그 로그에 남기지 않는다. 실패 응답은 코드 존재 여부를 노출하지 않도록 통일한다.

## 클릭 없는 봇 방어 — 미활성 후보

- Cloudflare Turnstile Invisible: https://developers.cloudflare.com/turnstile/concepts/widget/
- 서버 검증 필수: https://developers.cloudflare.com/turnstile/get-started/server-side-validation/
- 외부 계정·키·도메인·개인정보 안내가 없으므로 실제 활성화하지 않았다.
- 캡챠 토큰은 참가자 인증이 아니며 정적 파일 전체 스캔을 차단하는 방화벽도 아니다.
- 허용된 개발 AI는 User-Agent 이름이 아닌 별도 검증 가능한 최소권한 인증 또는 전용 개발 환경으로 접근시켜야 한다.
- 허용할 AI/경로/인증 방식과 배포 도메인은 미결정이다. 공용 우회 키를 프런트에 넣지 않는다.
- 페이지 이동마다 검증하지 않고 최초 코드 인증 등 민감 진입 지점에 한정하는 방향을 검토한다.
- 검증 실패를 성공으로 처리하지 않는다. 외부 검증 지연·장애는 기술 오류로 분리하며 실제 전환시간 QA가 필요하다.
