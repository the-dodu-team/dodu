## 2026-11-22 사진 제출 직후 판정 시작

- 원인: 판정은 30초 주기 워커에서만 시작되어 Render 측정(20회)에서 워커 대기가 평균 16.3초·p95 31.2초로 전체(제출→화면 평균 23.8초)의 대부분이었다. 실제 처리(사진 읽기+AI+저장)는 평균 3.0초.
- 변경: 제출 커밋 직후 전용 실행기로 판정 시작. 워커는 단계(차지·AI·저장)를 나누고 작업마다 짧은 트랜잭션으로 처리해 AI 대기 중 DB 연결·잠금을 잡지 않는다. 30초 워커는 안전망으로 유지.
- 검증: 신규 7건·백엔드 전체 325건 통과(건너뜀 1, R-46). 근거는 Decisions DEV-20261122-01. 운영 개선 후 측정은 배포 후 진행.

`PhotoRecoveryPolicy`는 T+30 이후에도 T 이전에 정상 접수된 동일 attempt만 `Evaluating` 상태에서 내부 복구할 수 있도록 한다. 새 사진 제출이나 완료·거절·기술실패·철회 attempt의 재처리는 허용하지 않는다.
