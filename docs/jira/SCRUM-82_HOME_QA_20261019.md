- 기준: 사용자 승인 월~일 집계 및 최종 인증 결과 반영, 첨부 핸드오프 디자인 스펙 섹션 1과 빈 상태 캡처, D04/D05/D11.

## 통과한 검증

현재 저장소의 TypeScript 소스를 직접 불러온 자동 검사와 실제 React 컴포넌트의 정적 렌더링을 사용했다.

- 토요일 성공 1건 + 일요일 예약/진행 중: 1번 중 1번 유지.
- 일요일 최종 성공: 2번 중 2번, 최종 미완료: 2번 중 1번.
- evaluating, techFailed, permissionBlocked, cancelled, withdrawn은 집계 제외.
- 미제출 pending mock의 마감 1ms 전은 미집계, 정확히 T+30분은 미완료. 판정 대기는 마감 이후에도 제외.
- 월요일/일요일 포함, 이전 일요일/다음 월요일 제외. KST 월요일 00:00에 이전 주 결과 제외.
- 빈 상태 문구가 첨부 디자인과 일치하며 그래프는 숨김. 최종 결과가 모두 미완료이면 횟수와 0% 그래프 표시.
- 날짜 안내: 같은 날, 자정 통과, 연도 변경, 오전/오후 전환. 연도는 생략하고 날짜가 바뀌면 종료 날짜도 표시.
- 인증 버튼: 시작 직전 숨김, 정확히 시작 시 활성, 정확히 마감 시 비활성.
- 프론트엔드 lint 및 TypeScript/Vite build 통과.

## 문구 확인 및 제한

- 다가오는 약속 빈 상태: “오늘은 약속이 없어요”, “오늘 해야 할 일이 있나요?”, “약속을 만들어보세요”, “약속 만들기”.
- 지난 약속 빈 상태: “이번 주의 지난 약속이 없어요”, “약속이 있다면 알려드릴게요”.
- 카드 제목, 수정하기, 전체 보기, 시작 시간, 인증 도구, 인증했어요, 약속 인증하기 확인.
- 디자인의 미래 약속 하단 “이 약속이 끝나면 새 약속을 만들 수 있어요” 대신 날짜 포함 인증 시간 안내를 표시하는 것은 사용자의 후속 요청을 따른다.
- 판정 대기/시간 종료/인증 완료 mock 하단 상태 문구는 첨부 문서에 동일 문구가 명시되지 않아 디자인 일치 확정 대상에서 제외했다. 임의로 새 문구를 추가하지 않았다.
- 아래 후속 브라우저 검사에서 새 약속 저장 후 이력 보존을 확인했다. 실제 기기 레이아웃, API 판정/서버 시간 검증은 실행하지 않았다.
- mock 상태는 메모리에만 보관된다. 실제 서버 결과 검증을 대체하지 않는다.
- 커밋, 푸시, Jira 상태 변경 및 댓글 작성은 하지 않았다. 백엔드 파일은 변경하지 않았다.

## 후속 브라우저 검증 및 날짜 단계 오류 수정

- 실제 App을 로드한 임시 검증 페이지에서 브라우저 클릭으로 생성·저장·인증·취소·재생성을 실행했다. 검증 페이지의 시각만 제어했으며 제품 소스의 시간 정책은 변경하지 않았다. 임시 HTML은 검증 후 삭제했다.
- 첫 예약 저장: 지난 약속 빈 상태 유지. 인증 성공 후 1번 중 1번.
- 다음 날짜 예약 저장: 이전 성공 및 월요일 표시 보존, 1번 중 1번 유지.
- 두 번째 예약의 미제출 마감: 2번 중 1번 및 화요일 미완료 표시.
- 세 번째 예약 저장: 앞선 성공·미완료 기록 모두 보존, 2번 중 1번 유지.
- 완료 날짜 생성 제한을 날짜·시간 화면의 다음으로 클릭에서 확인. 날짜 칩 아래 디자인 문구, 사용 완료 날짜 비활성, 다음으로 비활성. 다른 날짜 선택 시 오류 해제.
- 취소→재생성 1회 허용→재취소→추가 재생성 차단 확인. 붉은 날짜 칩과 “이미 약속을 한 번 다시 만들었어요. 다른 날을 선택해 주세요.” 표시.
- 5분 미만: 입력 아래 구체적인 최소 시각을 포함하는 디자인 문구. 72시간 초과: 다음으로 비활성 확인.
- 재생성 약속의 시작 시간 수정 비활성 확인.
- 하단 새 예약 날짜 확인. 브라우저에서 상단 날짜의 ‘일’이 빠지는 Intl 차이도 보정했다.
- 증빙: 사용자 로컬 `SCRUM-79-82-QA-20261019` 폴더의 date-limit.png, recreation-limit.png, time-too-early.png, history-retained.png, history-two-retained.png.

## 최신 PRD·회의 근거 및 종료 경계

- 사용자 제공 PRD v2.5(2026-09-27) §11 F-01은 운영값을 서비스 운영 정책에 위임하며, §18은 실제 종료일과 공식 종료시각을 운영안에서 확정하도록 명시한다.
- `docs/api/TIME_CONTRACT.md` §7·8 및 D03: T+30분 ≤ 공식 종료시각. 실제 값은 STUDY_PERIOD 데이터로 관리한다. 특정 종료일 또는 매일 자정으로 고정하지 않았다.
- 전달받은 종료시각을 공통 함수로 검사하며 생성·수정 날짜 화면, 제출 순간, 최종 저장에서 재검사한다.
- 개발 서버 전용 `mockInterventionEndsAt` URL 인자로 재현 가능. 예: `?preview=promise-time&mockInterventionEndsAt=2026-10-19T01%3A35%3A00Z`. 이 예시는 가상 종료시각이며 프로덕션에서는 URL 값을 사용하지 않는다.
- 브라우저: 현재 10:00/가상 종료 10:35 KST에서 10:05 선택·저장 허용, 10:10 선택은 디자인 문구 및 다음으로 비활성. 수정 화면에서도 10:10 선택 시 저장 비활성 확인.
- 자동 검사: 종료 30분 전의 1ms 이전/정확한 경계 허용, 1ms 이후/종료시각 불허. 생성·수정 React 오류 출력 검사.
- 재실행: `npm run test:home --workspace frontend`. 현재 소스의 집계·날짜·종료 경계와 React 렌더링을 검사한다. 증빙 추가: official-end-error.png. 임시 검증 HTML은 삭제했다.
- 2026-10-18 회의 녹취 마지막 합의: 지난 약속 제목, 등록 시 미집계, 최종 인증 결과 반영, 하단 월·일 안내. 월~일 집계는 이후 사용자 직접 지시를 따른다. 회의 요약의 공백 금지/취소 후 재생성 차단처럼 기존 확정 정책과 다른 표현은 새 정책으로 채택하지 않는다.
- 남은 범위: 운영 종료시각의 실제 API 전달, 서버 상태 복원 및 실기기 검증. UI mock 범위의 검증 통과이며 SCRUM-82 전체 완료나 운영 연결 완료를 의미하지 않는다.
