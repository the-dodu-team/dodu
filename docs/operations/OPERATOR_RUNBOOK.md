# 운영자 접근 코드 작업 안내 (Runbook)

상태: 초안. SCRUM-56 구현 기준. `[확인필요]`는 아직 팀 확인이 끝나지 않은 항목입니다.
근거: `docs/security/PARTICIPANT_ACCESS_CONTRACT.md` §5(재발급), §7(철회), §9(운영자 기능)

## 1. 무엇을 하는 도구인가

참가자의 접근 코드를 **발급·재발급**하고, 참가자의 **철회를 반영**합니다. 웹 API가 아니라
서버에서 명령어로 한 번 실행하고 끝나는 방식이며, 포트를 열지 않습니다.
실행할 수 있는 사람은 서버에 접속할 수 있고 DB 접속 정보와 pepper를 가진 사람뿐입니다.

| 명령 | 하는 일 |
|---|---|
| `issue` | 활성 코드가 없는 참가자에게 최초 코드를 발급합니다 |
| `reissue` | 기존 코드를 폐기하고 새 코드를 발급합니다. 열려 있는 세션과 알림 구독도 함께 종료합니다 |
| `withdraw` | 참가자 철회를 반영합니다. 코드 폐기, 세션·알림 구독 종료, 접근 비활성화를 한 번에 처리합니다 |

## 2. 실행 전 준비

필요한 환경변수는 다음과 같습니다. 값은 저장소와 문서, 채팅에 적지 않습니다.

| 이름 | 설명 |
|---|---|
| `DODU_ACCESS_CODE_PEPPER` | 코드 해시용 서버 비밀 값(32바이트 이상). **실행 중인 서버와 반드시 같은 값**이어야 합니다 |
| `DODU_DB_HOST` 계열 | DB 접속 정보. 로컬은 `DODU_DB_PORT`, `DODU_DB_NAME`, `DODU_DB_USERNAME`, `DODU_DB_PASSWORD` |

> pepper가 서버와 다르면 발급은 성공으로 보이지만, 그 코드로 입장할 수 없습니다.
> 코드를 전달하기 전에 서버와 같은 pepper를 쓰고 있는지 먼저 확인하세요.

## 3. 실행 방법

`operator` 프로필로 jar를 실행하고, 명령과 인자를 뒤에 붙입니다.

```
java -jar dodu-backend-<버전>.jar --spring.profiles.active=operator <명령> <인자>
```

### 공통 인자

| 인자 | 필수 | 설명 |
|---|---|---|
| `--participant=<UUID>` | 예 | 대상 참가자 ID |
| `--operator=<이름>` | 예 | 작업한 운영자 이름. 감사 로그에 기록됩니다(128자 이하) |

### 3.1 최초 발급

```
... issue --participant=<UUID> --operator=<이름>
```

성공하면 접근 코드가 한 번만 출력됩니다. 이미 활성 코드가 있으면 `ACTIVE_CREDENTIAL_EXISTS`로 거부되며, 이때는 재발급을 사용하세요.

### 3.2 재발급

```
... reissue --participant=<UUID> --operator=<이름>
```

- 기존 코드는 즉시 폐기되어 입장할 수 없습니다.
- 그 참가자의 열려 있는 세션과 알림 구독이 종료됩니다. 참가자는 새 코드로 다시 입장해야 합니다.
- 코드가 유출됐는지 서버가 구분할 수 없으므로, 재발급 횟수와 관계없이 항상 세션을 종료합니다.
- 활성 코드가 없으면 `NO_ACTIVE_CREDENTIAL`로 거부됩니다. 이때는 `issue`를 사용하세요.

### 3.3 철회 반영

```
... withdraw --participant=<UUID> --operator=<이름> --requested-at=<ISO-8601>
```

`--requested-at`은 참가자가 외부 채널로 철회를 **요청한 시각**입니다. 반드시 시간대를 붙입니다.

```
--requested-at=2026-10-25T14:00:00+09:00
```

- 요청 시각은 현재보다 늦을 수 없습니다(`WITHDRAWAL_REQUESTED_AT_INVALID`). 시간대가 없거나 형식이 틀리면 사용법 오류가 납니다.
- 반영 시각은 명령을 실행한 시각으로 자동 기록됩니다.
- **되돌릴 수 없습니다.** 철회된 참가자에게는 발급과 재발급이 모두 거부됩니다(`PARTICIPANT_WITHDRAWN`). 실행 전에 참가자 ID와 요청 시각을 한 번 더 확인하세요.
활성 약속을 `Withdrawn`으로 종료하는 일과 예약된 알림·자기보고를 무효화하는 일은 아직 이 명령에 포함되어 있지 않습니다(§6).

## 4. 종료 코드와 결과 해석

| 종료 코드 | 의미 |
|---|---|
| 0 | 성공 |
| 1 | 업무 규칙으로 거부됨. 화면에 `거부됨 [코드]`가 출력됩니다 |
| 2 | 명령이나 인자가 잘못됨. 사용법이 출력됩니다 |
| 3 | 예기치 못한 실패. 서버 로그를 확인하세요 |

| 거부 코드 | 뜻 | 조치 |
|---|---|---|
| `ACTIVE_CREDENTIAL_EXISTS` | 이미 사용 중인 코드가 있음 | `reissue` 사용 |
| `NO_ACTIVE_CREDENTIAL` | 재발급할 활성 코드가 없음 | `issue` 사용 |
| `PARTICIPANT_NOT_FOUND` | 참가자 ID가 없음 | ID 확인 |
| `PARTICIPANT_WITHDRAWN` | 이미 철회됐거나 접근이 중단된 참가자 | 되돌릴 수 없음 |
| `WITHDRAWAL_REQUESTED_AT_INVALID` | 철회 요청 시각이 없거나 미래임 | 시각 수정 |
| `OPERATOR_REF_INVALID` | 운영자 이름이 비었거나 128자 초과 | `--operator` 확인 |

## 5. 코드 전달과 보안 수칙

- 접근 코드는 **발급 시 한 번만** 표시되며 DB에는 해시만 저장됩니다. 잃어버리면 다시 볼 수 없으니 `reissue`를 사용하세요.
- 코드는 참가자 본인에게만 1:1 채널로 전달하고, 그룹 채팅·이슈·PR·문서에 붙여넣지 않습니다.
- 전달 후 터미널 화면과 명령 이력에 남은 코드를 정리합니다. 코드는 로그에 남지 않도록 만들었지만 터미널 출력은 보호되지 않습니다.
- 감사 로그에는 코드와 해시가 기록되지 않습니다. 기록되는 것은 작업 종류, 대상 참가자, 운영자 이름, 결과, 시각입니다.
- `--operator`에는 누구나 같은 이름으로 추적할 수 있는 본인 이름을 씁니다. 공용 이름을 쓰면 감사 의미가 사라집니다.

## 6. 감사 로그 확인

모든 성공과 거부가 `operator_audit_log`에 기록됩니다.

```sql
select action_type, result, operator_ref, detail, occurred_at
from operator_audit_log
where participant_id = '<UUID>'
order by occurred_at;
```

| result | 의미 |
|---|---|
| `SUCCESS` | 작업이 반영됨 |
| `REJECTED` | 규칙에 의해 거부됨. `detail.reason`에 거부 코드 |

`FAILED`(예기치 못한 실패)는 현재 기록하지 않고 서버 로그에만 남습니다.

## 7. 아직 이 도구에 없는 것

| 항목 | 상태 |
|---|---|
| 참가자 등록(participant 행 생성) | 별도 작업. 현재는 기존 참가자만 대상 |
| 철회 시 활성 약속을 `Withdrawn`으로 종료 | 약속 테이블 구현과 맞춰 연결 예정 |
| 철회 시 예약된 알림·자기보고 무효화 | SCRUM-57, 58에서 연결 예정 |
| 데이터 삭제 요청 처리 | SCRUM-58 |
| 로그아웃(`LOGOUT` 종료 사유) | 별도 작업 |

## 8. 문제가 생겼을 때

| 증상 | 확인 |
|---|---|
| 시작하자마자 DB 연결 오류 | DB 접속 환경변수, DB 실행 여부 |
| 시작 시 pepper 오류 | `DODU_ACCESS_CODE_PEPPER`가 비었거나 32바이트 미만 |
| 발급은 되는데 참가자가 입장하지 못함 | 서버와 pepper가 같은지 먼저 확인 |
| 종료 코드 3 | 서버 로그에서 예외 종류 확인(메시지에는 비밀이 포함되지 않도록 종류만 출력) |
