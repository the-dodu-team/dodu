# 사진 저장소 운영 기준

## 선택

자동 결제를 허용하지 않는 운영 조건에서는 Cloudflare R2·Supabase Storage를 운영 provider로 확정하지 않는다. provider가 확정되기 전까지 개발·로컬 검증은 백엔드가 지정한 비공개 마운트 볼륨을 사용하고, 운영 배포에서는 원본 사진 기능을 활성화하지 않는다.

- 버킷 공개 접근: 차단
- 객체 암호화: 운영 provider 확정 후 provider 기능과 애플리케이션 암호화 정책을 함께 검토
- 객체 키: 참가자 식별정보를 포함하지 않는 무작위 UUID 기반 키
- DB: `photo_asset.storage_key`와 콘텐츠 메타데이터만 저장
- 브라우저: S3 자격정보와 공개 URL을 받지 않음
- 업로드/조회/삭제: 백엔드의 `PhotoObjectStore` 경계를 통해 수행

## 자격정보

1. 자동 결제가 없는 고정비·선불형 운영 저장소가 확인되기 전에는 운영 자격정보를 발급하지 않는다.
2. 개발용 로컬 볼륨은 Git 추적 대상이 아니며, 사진 원본을 로그·테스트 출력·문서에 복사하지 않는다.
3. 운영 provider가 정해지면 환경별 자격정보를 분리하고 Secret Manager 또는 배포 플랫폼 secret에만 저장한다.
4. 운영 자격정보는 담당자가 발급·보관하고, 정기 교체 및 유출 의심 시 즉시 폐기·재발급한다.

## 보관·삭제

- 약속의 공식 개입 종료시각에 30일을 더한 시각을 `delete_due_at`로 계산한다.
- 삭제 worker는 due 시각이 지난 객체를 provider에서 삭제한 뒤 DB 메타데이터를 정리한다. provider 삭제 실패 행은 원본 없이도 재시도할 수 있는 삭제 작업으로 남긴다.
- 참가자 철회·삭제 요청은 연결된 객체와 메타데이터 삭제 작업을 즉시 예약한다.
- Lifecycle 자동 삭제는 provider가 확정된 뒤에만 안전망으로 추가한다. 정확한 30일 판정은 DB의 due 시각과 worker가 담당한다.

## 아직 필요한 운영 작업

- 자동 결제 없는 운영 저장소·배포 호스트·백업 방식 확정
- provider 확정 후 bucket/volume, 권한, 자격정보 발급 및 담당자 확인
- 실제 bucket policy, lifecycle rule, 업로드·삭제 smoke test
- Testcontainers 또는 별도 S3 호환 테스트 환경을 이용한 통합 테스트
