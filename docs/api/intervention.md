# SCRUM-64 개입 종료 경계 구현 작업

담당: 강민(mono). 큰 기능 브랜치: `feat/SCRUM-64-intervention-boundary`.
상태: 기반 코드 분리 완료, API·DB 통합 미완료. HTTP 엔드포인트 계약은 아직 확정하지 않았습니다.

## 근거와 범위

사용자 승인 D03/D04/D08/D10/D11과 서비스 정책 §5/§8/§13을 적용합니다.
dev의 기존 파생 문서에는 승인 전 값이 남아 있으므로 +30분 예약·48시간 설문 등 오래된 값을 신규 구현 근거로 사용하지 않습니다. 승인 결정 반영 문서는 기존 PR #3에 있으며 원문은 변경하지 않습니다.
Notion 기준 페이지는 2026-10-04 404로 최신 내용과 하위 항목을 확인하지 못했습니다.

## 순차 작업

1. 제출 API·DB 저장과 원자적 판정 예약 연결: 서버 인증 참가자와 약속 소유권을 확인하고, 동일 약속의 request ID/fingerprint retry·충돌을 분리하며, attempt 저장과 Evaluating 슬롯 예약을 하나의 DB 트랜잭션으로 처리합니다. 판정 실행은 저장 성공 뒤에 시작하고 실행 유실·중복 방지 계약을 정합니다. 서버 정상 접수 시각은 단순 요청 도착과 구분합니다.
2. 결과 반영: 소유권·현재 attempt·참가자 철회를 같은 상태 트랜잭션에서 검사하고 지연·중복 결과가 최종 상태를 덮어쓰지 않게 합니다.
3. 내부 기술복구: 마감 전 유효 접수 시도만 기존 attempt 기준으로 복구하며 신규 제출 창을 연장하지 않습니다.
4. 공식 종료 후 신규 개입 차단: 알림·수정·재생성·기술복구 재예약의 실제 사용 사례와 스케줄 실행 직전에 종료 및 상태를 재확인합니다. 3번의 접수된 시도 내부 복구와 신규 재예약은 구분합니다.
5. 자기보고 24시간 통합 검증: 최종 T 기준 안내·응답 기한과 대상 상태를 검증하며 미응답을 미시작으로 해석하지 않습니다.

번호는 큰 기능 안의 순차 하위 작업입니다. 전체 완료·통합 검증 전에는 dev 대상 PR을 열지 않습니다. 별도 큰 기능이 필요한 경우 범위·담당·의존성을 먼저 정합니다.

## 선행 의존성과 현재 한계

- DB·마이그레이션 기술 결정은 기존 문서상 은서 담당입니다. 해당 작업을 대행하거나 DB 제품을 임의 도입하지 않았습니다.
- 참가자 인증·활성 세션·약속 저장 모델과 사진 비공개 저장 계약이 연결되지 않았습니다. 클라이언트 participant ID나 접수 시각을 그대로 신뢰하는 임시 API를 만들지 않습니다.
- 메모리 판정 예약은 단일 서버 기반이며 영속 저장·다중 서버 잠금·원자적 제출 통합을 대신하지 않습니다. CodeRabbit의 실제 제출 지점 동시성 보장은 아직 미완료입니다.
- 현재 기능 파일은 기존 PR #3의 SCRUM-64 코드/테스트만 복사해 분리했습니다. 기존 브랜치와 PR은 보존하고 삭제·종료·force push하지 않았습니다. 중복 병합 방지는 기존 PR 범위 정리 후 처리해야 합니다.

## 확인한 동작

- 제출 retry 식별 전 인증 참가자/약속 소유자 일치와 철회 여부 검사; 다른 약속의 attempt 재사용 거절
- 서버 Clock 기반 예약/신규 제출 시간 경계와 공식 종료 게이트
- 약속 내부 retry·새 attempt·fingerprint 충돌 분류
- 단일 프로세스의 원자적 판정 예약 및 늦은 해제 방어
- 유효 접수 시각 기준 마감 후 판정 허용 및 철회/비판정 상태 거절

검증: 2026-10-05 루트 `npm run verify` 통과 — 프런트 lint·TypeScript·빌드, 백엔드 20개 테스트, JAR 패키징. 실제 API/DB/기기/AI 검증은 미실행입니다.

`PhotoAttemptRetryPolicy`는 도메인 분류이며 API 접근 제어나 원자적 예약을 대신하지 않습니다. 입력 참가자는 서버 인증 결과, 소유자·철회·attempt는 잠금/트랜잭션으로 읽은 서버 기록이어야 합니다. `NEW_ATTEMPT`는 제출 허용 결과가 아니며 시간·상태 검사와 원자적 저장이 추가로 필요합니다. fingerprint는 서버에서 계산한 요청 식별값을 연결해야 합니다. HTTP 오류 매핑 및 DB 연결은 남아 있습니다.
