# 홈 주간 인증 집계 기반 — SCRUM-62

담당: 강민. 브랜치: `feat/SCRUM-62-home-summary`. 현재는 서버 기록을 집계하는 도메인 코드이며 HTTP·DB·FE 연동은 미구현입니다.

근거: 승인 D01/D05/D08, 서비스 정책 §9, Flow·Log §7. 홈 PR #7의 월요일~일요일 KST 표시와 맞춘 기술 기준입니다. 새로운 행동 지표나 포인트·성공률을 도입하지 않습니다.

- `Clock`에서 한 번 읽은 서버 시각의 KST 날짜와 월요일 포함/다음 월요일 제외 범위를 사용합니다.
- 집계 귀속은 최종 예정 시작일 KST입니다. 사진 판정 시각·생성일·기기 시간으로 주를 바꾸지 않습니다.
- 입력은 DB에서 조회한 참가자 소유의 약속 최종 상태 스냅샷입니다. 사진 attempt나 event 행을 직접 집계하지 않습니다.
- 인증 집계 분모는 AuthCompleted + AuthIncomplete만 포함합니다. 취소·기술실패·권한문제·철회·아직 종료되지 않은 상태는 별도로 유지합니다.
- 같은 promise ID/동일 스냅샷은 1건으로 계산합니다. 같은 ID의 충돌 스냅샷은 내부 오류로 거절하고 임의로 한 결과를 고르지 않습니다.
- 다른 참가자의 행은 제외합니다. 이것이 API 인증·소유권 조회를 대신하지는 않습니다. 실제 엔드포인트에서는 서버 활성 세션·철회 검증과 참가자 범위 DB 조회를 먼저 연결해야 합니다.
- 단일 순회·해시 중복 제거를 사용합니다(O(n) 처리/O(n) 메모리). 실제 운영 DB 성능 향상 수치는 측정하지 않았습니다. 장기 이력 전체를 읽지 않도록 DB 날짜 범위 인덱스와 조회를 연결하는 작업이 남아 있습니다.
- 반환값은 숫자와 날짜만 포함하며 자기보고/사진/참가자 접근정보가 없습니다. 인증 완료를 실제 시작으로 설명하지 않습니다.

후속: DB(SCRUM-55)·세션·최종 상태 어댑터·읽기 일관성, API 계약과 권한/철회 오류, FE(SCRUM-69) 연결, 실제 동시 요청 및 집계 성능 검증. 홈의 미리보기 pending/verified 분모와 서버 최종 인증 분모를 그대로 동일시하지 않습니다.

검증: KST 월요일 양끝 경계, 예외·진행 중 상태 분리, 타 참가자 제외, 중복 제거·충돌 거절, 빈 주와 결과 맵 불변성을 테스트합니다. API/DB/기기 QA는 미실행입니다. Notion 기준 페이지는 2026-10-07 404입니다.
