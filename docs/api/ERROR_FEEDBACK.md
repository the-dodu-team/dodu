# 웹 오류 경계와 처리 결과 안내

## 적용 범위와 필요성

- 최상위 렌더·React 생명주기 오류는 AppErrorBoundary의 대체 화면으로 처리한다. 자동 저장 재전송·인증 삭제는 수행하지 않는다.
- 비동기 및 이벤트 처리 오류는 기능별 catch를 우선한다. 미처리 rejection 및 예외가 있는 전역 error는 마지막 방어선에서 일반 실패 토스트를 표시한다. 브라우저가 전달하지 않는 오류와 초기 번들 로딩 실패까지 보장하지 않는다.
- ToastHost는 오류 경계 밖에 둔다. 실패 원문·스택·토큰·사진·설문 내용은 전달하지 않는다.
- 사용자 조작 결과 안내는 필요하지만 주기적 조회마다 토스트를 띄우는 것은 불필요하다. 반복 조회 실패는 기존 상태 화면·본문 안내를 유지한다.

## 성공과 실패

- 환영 문구는 서버 onboardingCompleted=false 대상에게만 표시한다. 완료된 참가자의 재입장에는 표시하지 않는다. 이는 최초 로그인 기록이 아니므로 온보딩 미완료 재입장에는 반복될 수 있다. 엄밀한 최초 입장 1회 여부는 현재 API가 제공하지 않는다.
- 온보딩 완료 상태와 현재 기기 권한은 다르다. 완료된 참가자의 현재 권한 누락은 PermissionRecoveryGate에서 안내하며 전체 온보딩을 다시 열지 않는다.

- 입장, 약속 생성·수정·취소, 로그아웃, 온보딩 완료, 자기보고 제출·건너뛰기, 사진 접수에 성공 토스트를 연결한다.
- 성공은 5초 후 해제하며 실패는 닫기 전까지 유지한다. 성공 role=status, 실패 role=alert를 사용하고 포커스를 강제로 이동하지 않는다.
- 모달 중 안내가 가려지지 않도록 지원 브라우저에서는 수동 popover 최상위 레이어를 사용한다. 구형 브라우저에는 고정 위치 표시와 기존 본문 오류를 유지한다.
- 오류 원문 대신 기능별 안내를 사용한다. 저장 결과 불명은 확정 실패로 표시하지 않고 처리 상태 확인을 안내한다. 자동 재전송하지 않는다.
- 사진 접수 성공은 인증 성공을 뜻하지 않는다. 최종 AI 결과는 기존 판정 화면에서 표시한다. Push 연결 완료 표시는 실제 수신을 의미하지 않는다.
- 권한 거부는 기존 권한 복구 화면으로 안내하며 일반 기술 오류로 합치지 않는다.
- 자기보고 저장 저널 쓰기도 catch 안으로 옮겨 저장소 접근 오류 시 저장 중으로 고정되는 경로를 보호한다.

## 검증과 한계

- npm run test:integration-ui --workspace frontend: 35건 통과.
- npm run build --workspace frontend: 성공.
- DODU_TEST_BASE_URL을 로컬 preview로 지정 후 npm run test:browser-feedback --workspace frontend 및 test:browser-reentry: 통과. 합성 API 로그인 실패, 성공 자동 해제, 실패 닫기, 원문 비노출, 렌더 오류 대체 화면·재접속, 실제 저장 작업의 성공 토스트 확인.
- lint 오류 없음, 기존 경고 유지. diff 및 비밀값 검사 수행.
- 전체 백엔드·디자인 원본 대조·Production·실기기 QA는 범위 밖이며 미실행.
